# 版本管理

GitHub 仓库：`shuyuana666-cyber/sfhyl`。

## 分支与版本

- `main` 保存可发布源码，根目录即项目目录。官网、API 与完整 Vben 后台源码一起管理。
- 功能开发使用 `feature/<功能名称>`，修复使用 `fix/<问题名称>`，完成后合并到 `main`。
- 发布使用语义化版本标签 `v主版本.次版本.修订版本`；1.0.1 标签为 `v1.0.1`。每次发布同步更新根/API 包版本、API version 常量、后台公开版本参数与 CHANGELOG。
- 已发布标签保持固定；后续修复创建新提交及新版本。
- 服务器每个版本使用独立 `releases/<日期>-v<版本>` 目录，保留 API 镜像版本标签和数据库/媒体备份。

## 发布流程

1. 合并功能并更新版本与 CHANGELOG。
2. 构建官网、后台和 API，核对部署参数。
3. 提交源码并建立带说明的 `vX.Y.Z` 标签，推送 `main` 与标签。
4. 创建同名 GitHub Release，说明功能、配置变化和迁移步骤。
5. 用 `scripts/build-release.mjs` 构建发布目录；manifest 记录版本和源码提交。
6. 备份服务器，部署新目录，检查服务就绪后切换 `current`。部署记录列出目录、镜像、检查结果和回退位置。

运行环境 `.env`、密码、数据库转储、上传文件、开发日志、依赖和构建输出不进入 Git。后台的 `apps/web-ele/.env*` 仅包含 VITE 公共构建参数，按白名单纳入版本管理；它们不用于保存服务端密钥。

当前首次完整源码版本为 1.0.1。原 GitHub 初始提交保留；本机 `main` 目录为历史 1.0.0 基线。Vben 原嵌套 Git 元数据备份在本机项目父目录 `git-backups/admin-vben-original.git`，业务源码由项目根仓库统一管理。
