# SFHYL 平台功能与使用手册

版本 1.0　　更新日期 2026 年 10 月 14 日

## 1 平台入口与快速上手

### 1.1 访问入口

| 使用场景 | 地址 | 说明 |
| --- | --- | --- |
| 正式官网 | https://sfhyl.cn/ | 客户浏览车辆及公司服务 |
| 正式后台 | https://sfhyl.cn/admin/ | 员工维护内容、车辆和询盘 |
| 官网登录 | https://sfhyl.cn/login | 客户登录或注册，也支持管理员身份识别 |
| 客户账户 | https://sfhyl.cn/account | 客户查看个人资料与关联询盘 |
| 本地官网 | http://127.0.0.1:5173/ | 先在电脑上启动本地服务 |
| 本地后台 | http://127.0.0.1:5173/admin/ | 使用本地数据库与文件 |

正式环境和本地环境分别保存各自的数据。修改电脑上的内容后，需要另行执行部署或数据同步才会更新服务器。2026 年 10 月 12 日完成过一次本地数据库和媒体替换，此后的两套数据继续分别变化。

### 1.2 不同人员使用哪些功能

| 人员 | 主要工作 | 建议先阅读 |
| --- | --- | --- |
| 网站运营 | 图片、首页、公司介绍、联系方式、多语言文案 | 第 3、4、6、7 章 |

表中是岗位使用建议。账号实际可见菜单和可用操作，由后台当前角色权限决定。

### 1.3 第一次登录后台

1. 打开正式后台地址，输入管理员用户名或邮箱及密码。
2. 登录后确认左侧菜单是否符合岗位职责。
3. 进入“数据概览”，了解当前车辆与询盘情况。
4. 首次发布车辆前，先准备品牌、车辆资料和图片。
5. 首次修改网站前，先确认当前正在操作正式环境还是本地环境。
6. 操作完成后打开对应官网页面，检查实际显示结果。

账号由平台管理员创建。本手册不记录账号密码、服务器密码、API 密钥或会话令牌。

### 1.4 十分钟熟悉系统

建议依次查看“数据概览”“车辆列表”“图片库”“首页展示内容”“询价记录”。先学会筛选、查看详情和返回列表，再尝试编辑。用于练习的车辆可先保存为新草稿；正式内容的编辑应按第 3 章发布规则操作。

## 2 官网功能与客户操作

### 2.1 首页和语言切换

首页用于展示公司形象、服务优势、合作流程、服务地区、车辆与品牌。实际显示的模块由当前内容和页面展示规则共同决定。

顶部提供中文、英文、俄文切换。切换后检查导航、车辆名称、正文和按钮文字；后台未填写某种语言的内容时，部分区域会使用其他语言作为回退值。官网语言切换用于切换已保存的文本，人工录入的三语内容应分别维护。

手机访问时，点击页眉菜单按钮展开导航，再选择车辆、关于我们、联系我们等入口。点击页眉 Logo 可返回首页。

### 2.2 查找车辆

1. 从顶部导航进入“车辆”，或使用首页的浏览车辆按钮。
2. 按品牌、车型、价格区间、年份、里程及关键词缩小范围。
3. 品牌切换后，重新检查车型条件；筛选无结果时点击重置，再逐项增加条件。
4. 点击车辆图片、名称或详情按钮，进入车辆详情。
5. 如需与销售沟通，记录车辆名称和库存编号，或直接从车辆详情提交询盘。

官网筛选依据当前公开车辆数据。当前网页一次加载最多 100 条公开车辆后进行页面筛选和分页；车源规模超过该范围时，需要技术人员扩展目录加载方式。后台草稿、已下架、已删除或尚未满足公开时间条件的车辆，不作为正常公开车源展示。售出标记属于销售状态，若希望移除公开车源，另行执行下架操作。

### 2.3 阅读车辆详情

车辆详情包含图片轮播、车辆名称、价格、主要参数、说明和咨询入口。点击缩略图或左右切换按钮查看不同角度的图片。页面可能展示相关车辆，方便继续浏览。

价格为空或没有有效展示价格时，页面按询价方式显示。后台价格默认货币与录入值应一起核对；页面中的汇率换算信息供浏览参考，最终成交币种、价格和费用由销售确认。车辆 VIN 在公开数据中受到限制，客户需要核验具体信息时联系销售。

### 2.4 提交询盘

1. 在车辆详情打开咨询弹窗，或进入“联系我们”使用询盘表单。
2. 填写姓名，至少 2 个字符。
3. 在电话、WhatsApp、邮箱中至少填写一种有效联系方式。建议电话号码带国家区号。
4. 根据需要填写国家或地区、公司名称和咨询内容。
5. 如页面启用了验证码，先完成验证，再点击“提交询盘”。
6. 等待成功提示并记录询盘参考编号，避免连续重复提交。

从车辆详情提交时会附带意向车辆信息；表单还会记录来源页面和当前语言，便于销售跟进。通用联系表单的留言应尽量写清车型、数量、预算及目的地。

**填写示例**：计划采购 2 辆 2025 年 SUV，预算每辆 15,000 美元，交付至阿拉木图，希望了解库存、车辆状况及运输费用。

系统设有提交频率及重复内容检查。出现频繁提交提示时，先核对是否已有成功记录，再等待后续处理。通知邮件和即时通讯通知取决于部署配置，成功提示表示系统已接收该次表单。

### 2.5 使用电话和社交媒体入口

联系方式页面可展示电话、WhatsApp、Facebook、TikTok 等入口。点击 WhatsApp 会跳转对应聊天服务，聊天消息由该服务处理。站外聊天内容与站内询盘记录分别保存，客服应核对后台是否已有记录。

社交媒体链接未配置时，部分图标可能仍显示为未激活状态。运营应检查号码、链接和跳转目标，尤其是国家区号和完整 HTTPS 地址。

### 2.6 客户注册登录与个人资料

1. 进入官网“登录”，切换到“注册”。
2. 填写姓名、手机号码、邮箱和密码；公司名称可选。
3. 密码长度为 8 至 128 位。手机号和邮箱应使用本人可接收业务联系的信息。
4. 点击“创建账户”，成功后进入“我的账户”。
5. 已有客户使用手机号码或邮箱及密码登录。
6. 在账户页面修改姓名、公司、手机号码、邮箱后，点击“保存资料”。

手机号或邮箱已被占用时，应核对已有账户。修改手机号或邮箱后，下次登录使用更新后的资料。账户页面提供退出登录按钮。

### 2.7 查看我的询盘

登录客户账户后，“我的询盘”显示与当前客户账户关联的询盘、创建日期和状态。建议先登录再提交表单，便于后续查看。

匿名提交的历史询盘不会仅凭相同手机号或邮箱自动归入新注册账户。站内客户账户只查看本人关联记录，销售内部备注在后台维护。当前客户页面未提供订单付款、物流跟踪或自助找回密码界面；需要协助时使用站点联系方式联系工作人员。

## 3 后台界面与通用规则

### 3.1 菜单结构

| 一级菜单 | 主要功能 |
| --- | --- |
| 数据概览 | 车辆、询盘、素材统计，趋势和近期记录 |
| 车辆管理 | 车辆列表、新车、二手车、已售车辆、草稿、品牌及分类 |
| 首页管理 | Banner、模块、推荐车辆、品牌、优势、视频、公司简介 |
| 网站内容 | 首页展示内容、页面、导航、页脚、联系信息、社交媒体、SEO |
| 素材管理 | 图片库、视频库、文件夹、上传记录 |
| 客户管理 | 询价记录、联系留言、WhatsApp 来源、内部备注、导出 |
| 权限管理 | 管理员、角色权限、权限列表 |
| 系统管理 | 网站设置、翻译模型、存储、邮件、日志与系统信息 |

部分菜单是同一业务列表的快捷筛选入口。例如“新车管理”预设车辆类型为新车，“联系留言”预设询盘来源为官网。

### 3.2 列表筛选与批量操作

常见列表支持关键词、状态、日期、负责人或业务分类筛选。调整条件后按页面提供的查询或刷新按钮加载结果；找不到记录时，优先检查是否保留了历史筛选条件。

批量操作前先核对勾选数量、目标记录和目标状态。表格分页、筛选结果和已勾选记录可能影响操作范围；页面的确认提示是最终核对依据。CSV 导出用于下载业务数据，下载后在 Excel 中检查中文、日期和列内容。

### 3.3 保存和发布的实际含义

| 操作对象 | 保存或发布规则 |
| --- | --- |
| 新建车辆 | “保存”建立草稿；“保存并发布”校验后公开 |
| 已发布车辆 | 编辑后“保存”保留原发布状态，修改可能直接公开 |
| 首次首页展示内容 | 保存后可再执行“保存并发布” |
| 已发布首页展示内容 | “保存草稿”更新同一内容记录并保留发布状态，修改可能直接公开 |
| 普通页面 | 新建保存为草稿；已发布页面再次保存通常保留原发布状态 |
| 网站设置及导航 | 保存后通常直接供官网读取 |
| Banner 和推荐配置 | 保存后还要满足启用状态、有效期和展示条件 |

**编辑正式内容前先确认影响**：首页展示内容当前采用单条内容记录，已发布内容没有独立的待审核副本。需要等待统一上线的大改动，先在本地或外部文档完成审核，再集中修改。已发布车辆如果暂时不适合公开，先下架，再编辑和复核。普通页面的“保存草稿”在编辑既有已发布记录时也不会自动生成独立草稿。

大部分编辑页会提示尚未保存的修改。提示关闭、返回或离开前，确认是否已经保存成功。页面显示保存中时保持页面打开，尤其是包含自动翻译的车辆、品牌或页面操作。

### 3.4 多语言与链接录入

首页展示内容的多个区域同时提供中文、英文、俄文输入框，应分别填写。车辆及部分目录、普通页面使用中文输入，并在保存时调用配置的模型生成英文和俄文。自动翻译失败时保存会报错，应保留当前输入，检查模型配置后重试。

站内链接建议使用 `/vehicles`、`/about`、`/contact` 这样的相对路径；外部链接使用完整 HTTPS 地址。使用 `#about` 等页面锚点前，核对目标页面存在对应区域。完整复制链接时避免夹带空格。

### 3.5 数据概览

可选择近 7 天、30 天、90 天或自定义日期范围，自定义区间最多 366 天。页面可查看车辆总量、在售/已售/草稿、新车/二手车、今日/本周/本月询盘、未处理询盘以及图片和视频数量。

趋势图、热门询盘车辆、近期操作和近期登录帮助安排日常工作。统计卡片与具体列表可能使用不同口径，例如全部历史车辆与公开车源数量；需要查明单条数据时进入业务列表核对。

## 4 图片视频与素材管理

### 4.1 素材的组织方式

素材库保存图片和视频记录，业务内容通过素材 ID 引用实际文件。同一个素材可以用于多个页面。文件夹用于整理，移动文件夹归属通常保留原素材 ID 和公开地址。

建议按“车辆 / 库存编号”“首页轮播”“公司介绍”“员工”“服务流程”等用途建立文件夹；文件显示名称建议包含用途或车辆库存编号，便于后续搜索。

### 4.2 支持格式和上传限制

| 文件类型 | 当前支持 | 默认单文件限制 |
| --- | --- | --- |
| 图片 | JPEG、PNG、WebP、GIF、SVG | 15 MB |
| 视频 | MP4、WebM、MOV | 100 MB |

限制可由服务器配置调整，实际以上传提示为准。系统检查文件内容，仅修改扩展名不等于转换文件格式。界面存在 PDF 类型筛选，但当前上传校验仅接受表中格式。

JPEG、PNG 在启用图像处理时会转换为 WebP，并可能生成缩略图。默认最长边控制为 2560 像素、缩略图宽度为 480 像素；实际尺寸取决于原图和运行配置。品牌图标使用 SVG 时，文件会经过内容清理。

运营建议使用清晰、主体居中的图片；服务流程阶段图可按 1200 × 675 像素准备。其他栏目根据实际展示比例裁图，先用一张图片验证电脑端和手机端效果，再批量准备。

### 4.3 上传图片或视频

1. 进入“素材管理 → 图片库”或“视频库”。
2. 选择目标文件夹，必要时新建文件夹。
3. 点击“上传素材”，选择一个或多个文件。
4. 等待完成提示，检查上传后的图片、视频和文件大小。
5. 按名称、类型、上传日期或文件夹搜索刚上传的文件。
6. 如有失败，进入“上传记录”查看原因，处理后重新上传。

视频建议优先准备 MP4，并在目标手机和浏览器中试播。上传成功代表文件通过校验，浏览器播放还取决于视频编码；视频过大时先压缩，再上传。封面图片通常需要在具体页面或视频配置中单独选择。

### 4.4 编辑选择和替换素材

素材卡片可预览文件、编辑显示名称、移动目录或复制 URL。编辑车辆或首页时，点击素材选择器，在弹窗中筛选并选择已有文件；如需上传，可使用选择器提供的上传入口。

更换页面图片应在对应业务内容中选择新素材，再保存。重命名素材显示名称只影响管理识别；若要更换画面，上传新文件并替换引用。复制 URL 后，应在新标签页试开，确认可公开访问。

### 4.5 文件夹操作

“新建文件夹”会在当前目录创建子文件夹；在根目录操作则创建一级文件夹。重命名保持其所属目录。

删除文件夹时，该文件夹中的素材及子文件夹会移到上一级目录。素材文件本身和既有页面引用保留。因此，删除文件夹适合调整整理结构，清理文件应另行使用素材删除操作。

### 4.6 回收站和永久删除

回收站用于查看已有归档素材，提供恢复和永久删除。恢复后仍应核对所在目录和业务页面引用。

图片库的“彻底删除”和批量删除会移除文件、缩略图、衍生文件和素材记录。正在被车辆、首页或页面使用的素材，应先在业务内容中换成其他素材并保存，再清理旧文件。

**删除前核对**：确认选择的是旧素材，查清当前引用，并保留需要的原始文件。永久删除后，原地址会失效，恢复依赖完整备份。

### 4.7 上传记录

“素材管理 → 上传记录”用于检查文件名称、上传结果、耗时和失败原因。可按结果或时间筛选，便于排查文件过大、格式不支持或网络中断。

“全部清空”删除上传历史记录，已上传素材和业务引用继续保留。需要追查某次上传时，先保存必要信息，再清空历史。

## 5 车辆资料与发布管理

### 5.1 品牌车系车型与分类

品牌、车系、车型采用逐级关联：先选品牌，再选所属车系和车型。车辆分类用于业务分组，车辆标签用于补充推荐或特点标识。维护顺序建议为品牌 → 车系 → 车型 → 分类及标签 → 车辆。

在“车辆管理”对应菜单中新增或编辑目录项。品牌可维护名称、国家或地区、Logo 和 SEO；标签可设置颜色。品牌展示顺序和启用状态会影响相关显示，Logo 还要在官网检查。

车辆表单支持通过品牌搜索框快速创建品牌。快速创建后，建议回到“品牌管理”补充 Logo、名称和其他资料，避免产生相近名称的重复品牌。更换车辆所属品牌后，应重新核对车系和车型。

### 5.2 新增车辆的完整步骤

1. 上传车辆照片和视频，确认照片顺序及封面候选。
2. 进入“车辆管理 → 新增车辆”。
3. 在基础信息中填写中文名称、品牌、年份、车辆类型和库存编号等。
4. 在价格与参数中填写金额、货币、里程、车况及技术参数。
5. 在展示内容中填写中文摘要、正文、核心亮点和配置。
6. 在媒体素材中选择照片和视频，调整顺序。
7. 点击“保存”建立草稿，或点击“保存并发布”立即发布。
8. 返回车辆列表检查状态，再到官网检查车辆卡片和详情。

中文名称、品牌、年份为表单基础必填项。发布还要求至少一张可用图片。价格可留空，以询价方式展示。库存编号留空时由系统生成；人工编号应保持唯一、清晰且便于销售沟通。

### 5.3 主要字段填写说明

| 字段组 | 填写内容 | 需要核对 |
| --- | --- | --- |
| 身份信息 | 名称、库存编号、VIN、新车或二手车 | 名称与实车对应，VIN 按业务保密要求维护 |
| 品牌目录 | 品牌、车系、车型、分类、标签 | 上下级关联一致 |
| 时间地点 | 年份、生产日期、上牌日期、所在地 | 年份与生产上牌日期分别填写 |
| 价格 | 售价、原价、货币、价格备注 | 默认货币为 USD，录入前主动确认 |
| 使用情况 | 里程、里程单位、销售状态 | 数值和单位一致，已售及时更新 |
| 动力参数 | 排量、燃料、变速箱、驱动、发动机功率 | 单位和表达统一 |
| 车身参数 | 车身类型、门数、座位数、颜色、尺寸、整备质量 | 以实际车辆资料为准 |
| 新能源参数 | 电池容量、续航等 | 写清容量或续航单位和适用口径 |
| 展示内容 | 摘要、正文、亮点、配置 | 不同内容区各自保存和展示 |

**价格示例**：车辆报价为人民币 117,000 元时，应选择 CNY 并填写 117000。若货币保持 USD，页面会按美元价格处理，发布前务必核对。

### 5.4 描述与多语言处理

车辆编辑页主要输入中文名称、摘要和正文。保存时会调用自动翻译服务，生成英文和俄文内容。翻译服务响应可能比普通保存慢，保持页面打开，看到成功提示后再返回列表。

中文正文支持换行和经过清理的 HTML。核心亮点每行一项，适合填写关键配置、车况或服务信息。车辆配置字段需要有效 JSON 对象，可留默认空对象。

```json
{
  "天窗": "全景天窗",
  "座椅": "真皮座椅",
  "辅助驾驶": "自适应巡航"
}
```

JSON 使用英文双引号，项目之间用英文逗号分隔，末项后不加逗号。配置内容的自动翻译范围与名称正文不同，发布后应分别检查目标语言页面。

### 5.5 图片顺序与封面

车辆媒体支持多图及视频。通过拖动或上下按钮调整顺序，排序最靠前的图片自动作为封面，即使前面有视频，也要保证列表中至少存在一张图片。

建议照片顺序为车辆正前侧、另一侧、车尾、前排内饰、后排、仪表及细节。此顺序为运营建议，可按具体车辆调整。删除媒体行通常是解除该车与素材的关联，清理素材库原文件需到素材管理另行操作。

### 5.6 两组状态的区别

| 状态类型 | 选项 | 用途 |
| --- | --- | --- |
| 内容发布状态 | 草稿 DRAFT | 新建后待编辑或待确认 |
| 内容发布状态 | 已发布 PUBLISHED | 满足公开条件后展示 |
| 内容发布状态 | 已下架 OFFLINE | 暂停公开展示 |
| 内容发布状态 | 已归档 ARCHIVED | 历史归档状态 |
| 销售状态 | 在售 AVAILABLE | 可继续销售 |
| 销售状态 | 已预订 RESERVED | 已有预订，需与销售确认 |
| 销售状态 | 已售 SOLD | 已完成销售，前台可显示已售标记 |

标记已售后如需从公开车源中移除，还要下架。恢复在售同样不代表重新发布，操作后同时检查两组状态。

### 5.7 编辑复制删除与恢复

车辆列表可按关键词、品牌、车系、车型、分类、类型、推荐、发布状态、销售状态、年份和价格筛选。新车、二手车、已售和草稿箱提供预设入口。

“复制车辆”适合新建相似配置车源，复制结果为草稿。复制后逐项修改库存编号、VIN、价格、里程、车况和照片，防止沿用上一辆车的信息。预览官网用于核对公开效果，草稿未公开时应回到后台检查资料。

删除车辆会使其进入回收状态。通过列表“回收站”筛选找到记录后恢复，再检查状态并按需发布。批量操作支持发布、下架、推荐、取消推荐、标记已售、恢复在售、恢复或删除；以账号可用按钮和提示为准。

### 5.8 发布前检查

发布前逐项确认：名称和实车一致；货币及价格正确；品牌和年份正确；销售状态正确；至少有一张封面图片；详情图与当前车辆对应；中文描述无遗漏；英文俄文可读；联系方式可用。发布后用官网车辆列表查找库存编号或名称，再打开详情复查。

## 6 首页内容与展示管理

### 6.1 应该进入哪个页面

| 修改目标 | 优先入口 |
| --- | --- |
| 官网首页顶部横幅 | 首页管理 → 轮播图 |
| 关于我们顶部图片与三语标题 | 网站内容 → 首页展示内容 → 顶部轮播 |
| 活动 Banner 及有效期 | 首页管理 → 轮播图 |
| 首页服务优势卡片 | 首页管理 → 优势图标 |
| 首页展示哪些车辆 | 首页管理 → 推荐车辆，并检查车辆发布状态 |
| 服务流程和服务地区 | 网站内容 → 首页展示内容 → 自定义模块 |
| 公司介绍和介绍视频 | 网站内容 → 首页展示内容 → 关于我们 |
| 运输图片与员工卡片 | 首页展示内容对应标签页 |
| 视频列表与封面 | 首页展示内容 → 视频 |
| 页脚办公室和停车场 | 首页展示内容 → 办公室与停车场 |
| 电话邮箱和社交链接 | 网站内容对应设置，或系统管理 → 网站设置 |

首页管理的模块配置与官网模板并非逐项动态生成关系。保存后以官网实际显示为准，调整某个模块的任意 JSON 字段不保证改变当前页面布局。

### 6.2 首页展示内容的基本操作

1. 进入“网站内容 → 首页展示内容”。
2. 等待内容和素材加载完成，再选择标签页。
3. 修改三语文本，选择图片或视频，调整条目顺序与显示开关。
4. 根据需要保存并发布。对已经发布的内容，“保存草稿”同样可能更新线上，详见第 3.3 节。
5. 打开官网首页和关于我们，切换三种语言检查。
6. 再用手机宽度核对图片裁切和文字长度。

该编辑器的多个标签页属于同一份内容。保存前一并核对本次编辑过的各标签页；大改动建议提前记录原文和原素材。

### 6.3 顶部轮播与专题 Banner

“首页展示内容 → 顶部轮播”可添加、删除、排序轮播条目，选择图片、移动端图片、三语标题及显示状态。移动端图片用于小屏展示，建议保持主体清晰，避免将重要文字放在容易裁切的边缘。

“首页管理 → 轮播图”提供活动记录的唯一标识、标题、副标题、PC 图片、移动端图片、按钮文字、跳转链接、打开方式、状态和起止时间。只有启用且处于有效期的 Banner 才进入公开 Banner 数据。

当前官网首页优先使用有效 Banner 数据；没有可用 Banner 时，才回退到“首页展示内容”的顶部轮播。“关于我们”首屏主要读取后者。只修改顶部轮播后首页未变化时，先检查首页管理中是否仍有有效 Banner。首页首屏主要按钮按当前模板跳转车辆目录和关于我们，Banner 配置的所有按钮字段并非都会被该模板展示。

### 6.4 服务优势

进入“首页管理 → 优势图标”，新增或编辑优势项，维护标题、说明、图标或图片、顺序和显示状态。多语言内容按字段提示填写。

首页目前将优势内容作为卡片展示。建议一张图对应一个优势，例如质量检验、国际运输、专业选车、售后支持；四个标题和说明保持近似长度，避免卡片高度差异过大。

### 6.5 首页推荐车辆

1. 先确认目标车辆已经发布且满足公开条件。
2. 进入“首页管理 → 推荐车辆”。
3. 在推荐配置中选择车辆，设置标签、有效期、启用状态和顺序。
4. 检查页面上方“官网实际展示”的车辆及来源。
5. 到官网核对车辆顺序、封面和显示数量。

推荐选择通常优先使用有效推荐配置，其次使用车辆推荐标记，最后使用公开车辆自动补充。首页车辆模块的显示开关和数量也会影响最终结果。希望撤掉某辆推荐车时，先检查是否同时存在推荐配置和车辆推荐标记。

### 6.6 公司介绍运输员工与视频

“关于我们”标签页维护模块标题、正文、按钮、介绍视频及封面。正文支持多语言内容；介绍视频和封面要分别选择。

“运输与交付”维护运输图片及说明。“员工”标签页维护员工图片、姓名、职位和简介，标签名称可能使用当前模块标题。各区可显示或隐藏、添加条目、排序或移除条目。

“视频”标签页的每条记录可选择视频、封面和三语标题。发布后检查实际播放、音量、拖动进度及封面；不同设备上均需试播。

### 6.7 快捷导航与地点

快捷导航维护名称、链接、显示状态和顺序。发布后检查链接是否到达预期页面或锚点，空地址应补齐或隐藏条目。

办公室与停车场维护地点类型、三语名称、地址及地图链接。多地点适合逐条录入，排序决定展示顺序。页脚和联系我们使用的公司信息要保持一致；地图链接保存后应试开确认落点。

### 6.8 自定义模块与服务流程阶段图

自定义模块支持设置显示开关、展示页面、展示位置、三语标题、正文、图片或视频，以及可选按钮。展示页面可选仅首页、仅关于我们或两处，展示位置根据页面范围提供。

操作顺序为新增模块 → 选择展示页面和位置 → 填写三语内容 → 选择素材类型和文件 → 填写按钮链接 → 调整顺序 → 保存发布 → 到两处页面检查。

既有“服务流程”模块提供每个阶段的独立配图。可在“服务阶段配图”中分别选择第 1 至第 5 阶段图片；阶段图缺失或加载失败时会使用通用图片。建议保持阶段数量、标题、内容结构及图片对应关系。

既有服务流程、服务地区和公司优势等模块使用特定内容结构和标识。日常更换文字和图片时保留原模块，不要通过删除再新建来替代，以免影响专门布局。“清空全部”会移除对应内容列表，操作前核对模块范围。

## 7 网站页面导航与联系信息

### 7.1 普通页面管理

“网站内容 → 页面管理”可保存公司说明、服务介绍等页面记录。新增时填写中文标题、摘要、HTML 正文、分享图和 SEO 信息；按需要保存草稿或保存并发布。保存中文内容时，部分字段通过翻译服务生成英文和俄文。

**访问入口规则**：普通页面记录发布后可供公开接口读取，但当前官网主要路由为首页、车辆、车辆详情、关于我们、联系我们、登录及账户。后台新建页面不会自动生成对应的可视页面路由。新增独立服务页时，需要技术人员接入展示地址，再由运营配置导航。

专用的“首页展示内容”请使用对应编辑器维护；页面列表中如见到相关专用记录，应保留其结构，避免用普通正文编辑器覆盖。

### 7.2 导航菜单

1. 进入“网站内容 → 导航菜单”，新增或编辑菜单项。
2. 填写唯一标识、中英文名称，可选俄文名称。
3. 设置链接、打开方式、排序、启用状态及按需设置父级。
4. 保存后到官网桌面端与手机端点击验证。

当前页眉保留首页、车辆、关于我们、联系我们等核心导航。匹配核心标识的后台记录可影响部分名称或链接，但隐藏或删除记录不保证移除模板内的核心入口。关于我们、登录及特定保留项还有独立处理。后台支持父子关系，当前页眉展示以一级入口为主；多级交互需技术人员确认页面支持情况。

### 7.3 网站名称与 Logo

进入“系统管理 → 网站设置”，在“基础信息”维护站点名称、简称、公司名称、默认语言和货币等；在“品牌标识”维护 Logo、移动端 Logo、Favicon 和分享图片。

当前官网页眉及后台品牌区域主要读取 Logo 地址，部分图片字段用于预留或特定场景。保存后分别检查官网、登录页和后台，不要只依据设置表单判断所有位置已经生效。Favicon 可能被浏览器缓存，可新开窗口检查。

### 7.4 联系方式与社交媒体

联系方式支持电话、WhatsApp、微信、邮箱、营业时间和地址。社交媒体支持 WhatsApp、Facebook、Instagram、YouTube、LinkedIn、TikTok、X 和 VK 等字段；官网实际图标依页面模板显示。

WhatsApp 优先使用社交媒体分组中设置的完整链接；留空时，官网尝试从联系分组号码生成链接。建议号码包含国家区号，完整链接使用 `https://wa.me/国家区号号码` 的形式，保存后实际点击测试。

公司总地址与“办公室与停车场”多地点列表分别维护。更换业务联系方式时，两处内容及自定义正文中的旧号码也应一起检查。

### 7.5 页脚 SEO 与维护模式

页脚管理用于维护版权及备案信息。SEO 分组用于保存站点默认标题、关键词和描述，车辆、品牌和页面还可能有各自字段。SEO 数据的存储与搜索引擎实际展示并非同一环节；搜索结果更新需要抓取，具体页面是否使用某个 SEO 字段由前端实现决定。

网站设置中的“功能开关”包含维护模式和维护提示。需要计划维护时先准备提示文案和恢复时间，启用后用未登录浏览器核对官网；维护结束后关闭并确认官网恢复。维护模式不代替停写、数据库备份或部署检查。

## 8 询盘接收与客户跟进

### 8.1 询盘入口与来源

“客户管理 → 询价记录”用于集中查看线索；“联系留言”预设来源为 WEBSITE，“WhatsApp 咨询”预设来源为 WHATSAPP，“数据导出”提供导出入口。这些页面使用同一套询盘数据。

官网咨询表单通常形成官网来源记录。WhatsApp 菜单用于筛选已经存在的相应来源数据，单击站外 WhatsApp 链接不等于同步聊天内容。系统界面存在“手工录入”“其他”等来源筛选，日常页面是否提供新增入口以实际按钮为准。

### 8.2 查看和筛选

1. 进入询价记录，先查看“新询盘”和未分配记录。
2. 使用客户姓名、电话、邮箱、公司等关键词查找。
3. 根据需要筛选状态、来源、负责人、起止日期。
4. 打开详情，核对客户联系方式、国家、公司、留言及意向车辆。
5. 有来源页面或推广参数时，结合这些信息了解客户背景。

询盘中的 IP 和来源信息用于辅助定位，实际客户需求应通过沟通确认。不同菜单可能保留来源筛选，找不到记录时回到总列表重新查询。

### 8.3 分配负责人和记录备注

在详情“负责人”处选择员工并确认分配。负责人负责后续联系和状态更新；多人协作时，建议明确主负责人，其他人员通过内部备注记录协作结果。

“内部备注”输入沟通时间、需求、报价、答复和下一步安排，再点击“添加备注”。内部备注用于员工跟进，客户账户不展示这些备注。跨询盘查看跟进内容时进入“客户管理 → 客户备注”。

**备注示例**：10 月 14 日 10:30 已通过 WhatsApp 联系。客户关注 2025 年 SUV，目的地阿拉木图，需 2 辆。已发送库存照片，待确认预算后报价，计划 10 月 15 日再次联系。

### 8.4 询盘状态说明

| 状态代码 | 中文含义 | 建议使用时机 |
| --- | --- | --- |
| NEW | 新询盘 | 系统接收，尚未联系 |
| CONTACTED | 已联系 | 已进行首次有效联系 |
| FOLLOWING | 跟进中 | 需求沟通或资料往来中 |
| QUOTED | 已报价 | 已发送报价，等待反馈 |
| WON | 已成交 | 业务确认达成 |
| LOST | 已流失 | 已确认本次未成交 |
| INVALID | 无效 | 重复、垃圾或无效线索 |

以上是建议工作顺序，系统提供状态更新操作，员工按实际结果选择。归档适合处理结束后整理历史线索；归档前先写清最终结果。

### 8.5 批量处理与导出

选中多条询盘后，可批量更新状态或分配负责人。操作前确认选中的是同一处理阶段或同一人员负责的记录，避免把未联系客户统一标为已报价。

拥有导出权限时，按需要设置筛选条件并导出 CSV。导出文件包含业务线索与联系方式，应按团队的客户资料管理要求保存和共享。对外发送材料时另行整理适合公开的内容。

### 8.6 建议的每日跟进顺序

先处理新询盘与未分配线索，再处理约定今日联系的客户，随后检查已报价但未反馈的询盘，最后补齐备注和状态。该顺序是运营建议，系统内部备注中的计划时间需要员工主动查看，当前界面未提供独立的自动跟进提醒配置。

## 9 管理员角色与权限

### 9.1 后台员工与官网客户的区别

后台管理员账号用于管理车辆、内容和询盘；官网注册账户用于客户资料和本人关联询盘。两类账号分别管理，官网注册不获得后台员工权限。

### 9.2 新增和维护管理员

1. 进入“权限管理 → 管理员”，点击新增。
2. 填写用户名、邮箱、显示名称和初始密码。
3. 选择符合岗位职责的角色，确认账号状态。
4. 保存后让员工使用自己的账号登录，检查可见菜单和操作范围。
5. 后续在编辑中调整邮箱、显示名称、状态和角色。

管理员初始密码至少 12 位，并包含大写字母、小写字母和数字。离岗或暂停工作的员工应及时调整账号状态；交接时使用新员工自己的账号，便于日志追溯。

账号密码管理以当前后台入口和管理员处理流程为准。当前官网客户账户页未提供密码修改或找回界面，涉及客户密码协助时交由平台管理员处理。

### 9.3 内置角色与权限调整

| 角色 | 定位 |
| --- | --- |
| 超级管理员 | 平台全部功能和权限配置 |
| 内容运营 | 内容、首页、导航与素材维护 |
| 车辆编辑 | 车辆、品牌目录及关联素材 |
| 客户客服 | 询盘查看、跟进、分配及相应业务操作 |
| 其他已有角色 | 以角色权限页面实际授权为准 |

内置角色也需要查看实际权限，角色名称本身不代表拥有每个相关按钮。例如内容运营默认可查看部分网站设置，但修改设置还需要更新权限。

进入“角色权限”，新增时设置角色编码、中英文名称、状态及权限。可按模块勾选，保存后检查关联员工的实际菜单；如界面仍显示旧权限，可退出后重新登录验证。

### 9.4 常见权限组合

查看与编辑是两类权限，编辑与发布也可能分开。素材上传、删除、文件夹操作，询盘查看、备注、分配、导出，各自可能需要不同授权。

“权限列表”展示系统登记的权限码，用于核对配置。系统角色和最后一个有效超级管理员有保护机制，调整前确保保留可管理角色和账号的有效人员。

## 10 系统设置与运行状态

### 10.1 自动翻译模型配置

进入“系统管理 → API 模型配置”，维护协议、Base URL、API Key 和模型 ID。协议可选 OpenAI Compatible 或 Anthropic Compatible；选择与实际服务接口相匹配的选项。

1. 从服务提供方取得接口地址、密钥和可用模型 ID。
2. 按字段填入协议与 Base URL，避免将浏览器聊天网址当作 API 地址。
3. 首次配置输入 API Key；后续密钥框留空会保留原密钥。
4. 保存后查看密钥是否已配置。
5. 用一条待发布车辆或普通内容的保存流程核对翻译结果，确认英文和俄文质量。

车辆等内容保存时会调用翻译服务，服务配额、网络、模型 ID、协议或返回格式异常都可能导致保存失败。该页面的“保存成功”表示配置已存入系统，实际模型请求仍需要业务保存验证。

### 10.2 文件存储和邮件设置

“文件存储”用于查看当前驱动、公开地址和凭据配置状态；“邮件设置”用于查看 SMTP 相关运行配置。当前这些页面以状态查询为主，服务器参数调整由负责部署的人员完成。

当前生产媒体使用本地持久存储，文件通过 `/uploads/` 公开访问。历史 MinIO 对象和原服务保留用于兼容及回退。数据库保存素材记录和关联，实际图片视频保存在文件存储中，备份需两者一起处理。

邮件与 WhatsApp 通知是否启用，以运行配置为准。客服应定期检查后台询盘列表，避免只依赖外部通知。

### 10.3 日志与系统信息

| 菜单 | 用途 | 排查时先看什么 |
| --- | --- | --- |
| 操作日志 | 查询谁修改或删除了业务记录 | 操作者、时间、资源、操作类型 |
| 登录日志 | 查看登录成功失败及来源 | 账号、时间、结果和 IP |
| 系统日志 | 查看运行事件和错误 | 错误时间、信息、请求标识 |
| 系统信息 | 查看当前服务状态与信息 | 数据库、缓存、存储或版本等可见信息 |

向技术人员反馈时，提供环境、菜单、操作时间、记录 ID、错误提示和请求标识。截图避免包含密码、API 密钥和完整会话数据。

## 11 常用工作流程

### 11.1 发布一辆新到店车辆

先收集实车资料和报价，建立素材文件夹并上传照片；确认品牌目录后新建车辆，核对货币、里程和车况，选择图片顺序并保存草稿。审核完成后发布，在官网检查三种语言、封面、详情及咨询入口。需要首页推荐时再配置推荐车辆，并检查首页实际展示。

**完成标准**：官网能找到该车，数据与实车一致，售价和货币正确，图片可打开，销售知道对应库存编号。

### 11.2 已售车辆停止推广

先将销售状态标记为已售，取消推荐配置和推荐标记；若团队要求不再公开展示，再执行下架。检查首页及车辆目录，必要时核对其他自定义正文或活动 Banner 中的车辆链接。历史询盘和车辆记录保留，便于后续查询。

### 11.3 更换首页主图

先上传新图片及移动端图片，记录原素材；进入“首页管理 → 轮播图”替换有效 Banner 的图片及标题，确认启用状态和有效期。若首页使用回退轮播，再修改首页展示内容中的顶部轮播。保存后到官网查看电脑和手机效果。确认新图片无误且旧素材没有其他引用，再按需要清理旧素材。

### 11.4 更新服务流程配图

准备五个阶段的图片，进入首页展示内容的自定义模块，找到既有服务流程模块，逐阶段选择对应配图。保留原模块标识和正文结构，发布后逐一点击五个阶段，确认文字、图片和阶段顺序一致。

### 11.5 跟进新询盘

客服先打开详情核对联系方式和车辆，分配负责人，完成首次联系后更新状态并写内部备注。报价、沟通、成交或流失后继续更新状态，处理结束再归档。站外沟通结果由员工补充到后台。

### 11.6 修改公司电话或邮箱

进入联系方式分组更新号码或邮箱，再核对社交媒体 WhatsApp 链接、办公室与停车场、自定义正文、页脚和车辆描述中是否还有旧信息。保存后在官网首页、联系页和手机端实际点击验证。

### 11.7 新员工加入或岗位变更

管理员建立独立账号并分配最合适的角色，员工首次登录验证菜单和业务按钮。岗位变化时调整角色，离岗时调整状态，并确认未完成询盘已经交接给新负责人。

## 12 常见问题与处理方法

### 12.1 保存后官网没有变化

先确认正在编辑正式环境，并已收到成功提示；再检查发布状态、模块显示开关、Banner 或推荐有效期。首页轮播优先检查有效 Banner，关于我们轮播检查首页展示内容的顶部轮播，首页车辆检查推荐配置和车辆推荐标记。刷新官网，必要时等待短时缓存更新；仍有问题时查操作日志并记录时间。

### 12.2 点击保存时一直等待或翻译失败

先保留表单中的中文内容，等待当前请求结束。车辆、品牌和普通页面保存可能调用翻译服务。管理员检查 API 模型协议、地址、模型 ID、密钥状态、配额和网络，再重试。避免连续点击保存造成重复请求。

### 12.3 发布车辆提示缺少图片

在媒体素材中确认已经选择图片，只有视频不满足发布封面要求。检查图片记录是否仍有效、是否在回收站；重新选择图片后保存发布。

### 12.4 车辆没有出现在官网或首页

先检查车辆是否已发布、是否被删除或设为下架，再检查公开时间条件和筛选条件。首页还受推荐配置、推荐标记、模块启用与数量控制。后台新增草稿需要完成发布，标记在售也需要与发布状态一起核对。

### 12.5 图片显示异常或视频播放失败

先从素材库预览并复制 URL 直接访问。图片只在手机端异常时，检查移动端素材和裁切；视频文件可下载但播放异常时，检查编码并尝试导出常用 MP4。迁移后大量媒体异常时，让技术人员同时核对数据库和存储文件。

### 12.6 素材删除提示仍被引用

先查该素材是否用于车辆封面、车辆图库、首页内容、Banner、品牌或普通页面。进入使用位置更换素材并保存，再回到素材库删除。草稿或专用内容中保留的引用也可能需要处理。

### 12.7 删除了文件夹但图片还在

删除文件夹会把内容移到上一级目录。回到父目录或根目录查找。需要删除实际文件时，单独使用素材删除操作，并先确认业务引用。

### 12.8 客户说已联系但后台没有新询盘

先确认客户使用的是站内表单还是站外 WhatsApp、电话或邮箱。表单需要出现成功提示；站外沟通不自动等同于新后台询盘。后台查询时取消来源、日期和负责人筛选，并按手机号或邮箱搜索。

### 12.9 客户账户没有历史询盘

确认客户登录后提交的询盘是否关联当前账户。匿名历史记录不会只凭相同联系方式自动加入新账户；如需核对历史需求，由客服通过后台查询。

### 12.10 看不到菜单或保存按钮

检查当前账号状态和角色，分别核对查看、编辑、发布、导出等权限。角色修改后退出重新登录验证。若只有某类业务入口缺失，检查其对应权限，而非反复刷新页面。

### 12.11 登录失败或被临时锁定

确认使用的是后台账号还是官网客户账号，以及用户名、邮箱或手机号是否正确。连续失败可能触发临时锁定，先停止反复尝试，由管理员核对账号状态和登录日志。后台默认失败次数和锁定时长可由部署参数调整。

### 12.12 普通页面发布后打开却回到首页

当前官网没有通用动态页面路由。联系技术人员为该页面接入展示入口，再把实际可访问地址放入导航。页面后台记录成功保存和前端入口接入需要分别完成。

### 12.13 已发布内容点了保存草稿却在线上变化

首页展示内容保存时保留原发布状态，并更新同一内容记录；已经发布车辆的普通保存也可能更新公开资料。先用原文和原素材恢复需要撤回的修改，再安排正式变更时间。涉及待审核改版，先在本地准备完整内容。普通页面编辑后的保存也保留既有状态，需要区分首次草稿和已发布记录。

### 12.14 导出 CSV 中文或格式异常

在 Excel 中使用数据导入并选择 UTF-8，手机号、库存编号等字段按文本导入，避免自动科学计数或丢失前导符号。核对筛选范围和记录数量后再共享导出文件。

## 13 本地使用与数据维护

### 13.1 在电脑上打开本地系统

1. 在项目目录运行 `start-dev.bat`。
2. 保留启动窗口，等待官网、后台、API 和图片检查完成。
3. 使用本手册第 1.1 节的本地地址访问。
4. 单个服务意外退出时，启动器会尝试重启。
5. 停止本次启动的服务时，在启动窗口按 Ctrl+C。

本地服务复用情况及运行错误可查看 `logs/dev/`。内部端口由启动器和开发代理管理，日常直接使用 5173 的官网及后台地址。

### 13.2 数据库与文件一起备份

数据库保存车辆、页面、账号、询盘和素材路径；实际图片和视频保存在文件存储。完整备份至少包括数据库、实际媒体文件、对应版本程序及必要运行配置。只备份 SQL 会缺少文件，只拷贝图片也缺少业务关联。

本地素材可能分布在项目根目录和 API 目录下，迁移时按数据库引用核对实际文件。日常运营避免直接在 Windows 目录或服务器卷中删除文件，应通过素材库操作。

### 13.3 更新服务器的建议顺序

由负责部署的人员先核对源码和环境，构建官网、后台与 API，备份线上程序、数据库和媒体，再在临时环境导入验证。正式替换数据库时暂停写入并保存最终备份，切换后核对车辆、页面、账号、文件哈希、公开图片、视频和日志。

本地数据库整体替换会覆盖服务器在上次同步后新增的询盘、账号和内容。执行前应明确数据基准，提前导出需要保留的线上记录并制定合并方案。日常运营改图、改车和跟进询盘可直接在正式后台完成，无需每次整体替换数据库。

具体命令、路径和恢复步骤参阅项目部署手册及对应部署记录。恢复或回滚时，由运维人员按同一版本的程序、数据库、媒体和配置一起核对。

### 13.4 建议的日常检查

每天检查新询盘、公开车辆销售状态、首页和联系方式。每次发布后检查三种语言及电脑手机布局。每周检查长期未跟进询盘、失效链接、无用素材和账号状态。备份频率及保留周期由团队按业务更新量确定，并定期安排恢复验证。

## 14 功能边界与菜单速查

### 14.1 当前使用时需要记住的规则

1. 本地和正式数据分别变化，发布程序和替换数据库是独立操作。
2. 首页展示内容的“保存草稿”对已发布记录可能直接生效。
3. 已发布车辆普通保存可能更新公开资料，需暂停展示时先下架。
4. 车辆销售状态和发布状态分别管理，已售不自动等于下架。
5. 普通页面新增后需要前端接入展示入口。
6. 模块、导航、SEO 和图片字段是否显示，取决于当前官网模板。
7. 当前支持的上传格式以文件校验规则为准，PDF 筛选不代表支持上传 PDF。
8. WhatsApp 跳转、邮件往来和电话沟通由员工补充到后台跟进。
9. 客户匿名历史询盘不自动归入新注册账户。
10. 已保存的设置和模型服务实际可用性，需要分别验证。
